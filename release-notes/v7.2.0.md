# v7.2.0

Security-hardening release of the `orng.wax` 2-of-3 threshold member, closing the oracle-side
findings of the October 2026 RNG review (WBP-2067, epic WBP-2063). Same code as GitHub release
`7.2.0` (`worldwide-asset-exchange/wax-rng-oracle` `9f0ea8c`). Full detail in
[`CHANGELOG.md`](../CHANGELOG.md) §7.2.0; this file is the operator view.

## What changed

- **`@waxio/rsa-threshold-signatures` 2.0.0** (from 1.3.0) and `node-forge` floored at 1.4.0; the
  floors are asserted in CI, in the GitHub workflow and inside the `Dockerfile_eks` build.
- **Vendored contract source and test artifacts are `orng.wax` v3.4.0** (live since 2026-10-29).
- **A member with a wrong / mismatched share or index no longer starts.** On boot it checks its
  share against the on-chain `pubkeys` row for the active version and its configured share index
  against `oracles.a[<nodeOwner>].oracle_index`, and exits 1 on any failed check, logging
  `Boot self-check FAILED: … (<CODE>)` / `… failed checks: <names>` (names only, never values).
  Expect a visible crash loop instead of a member that signs and fails every combine. If the chain
  RPC is down (or a node is still replaying) at boot it retries for about a minute
  (`BOOT_CHECK_RPC_RETRIES` × `BOOT_CHECK_RPC_RETRY_BASE_MS`) and then exits 1 as well — the restart
  is the retry. This applies to `READONLY_MODE` replicas too.
- **Requests of another key version are skipped**, not signed: after a `setpubkey` rotation the
  members must be re-keyed and restarted (the log says so once per version;
  `key_version_skipped` metric).
- **`/health-check` carries `bootCheck`** (`ran`, `ok`, `rpcReachable`, `activeKeyFound`,
  `oracleIndexMatches`, `shareConsistent`, `activeVer`) and returns 500 unless the check passed.
- **A poisoned partial on chain no longer stalls a request.** The combine skips zero / out-of-range /
  malformed partials and tries k-subsets; the member logs `Combine diagnostics {…rejectedShares,
  failedSubsets, suspectShareIndices…}` with the job id and its own oracle index, and emits
  `combine_rejected_part{idx}` / `combine_suspect_share{idx}` / `combine_failed{code}` metrics. A job
  whose parts genuinely cannot combine is parked until its on-chain parts change (`… parked until
  parts change` in the log) rather than retried identically. The matching Slack alert is throttled
  to one per minute per member, with a suppressed count.
- **`/version` reports `7.2.0`**, and the image tag is `v7.2.0` — one number (see `CHANGELOG.md` →
  *Version scheme*; the v6.0.0 image reported `7.1.4`).
- **`NODE_ENV=production` is baked into the image**; the infra env still sets it too. The process
  refuses `NODE_ENV=test`.

## Why

- **ORC-3 / SIG-5 — a member could start with the wrong share and sign garbage forever.** Nothing
  checked the configured share against the on-chain modulus or the configured index against
  `oracles.a`; a mis-seeded member would submit partials that never combine. The boot self-check
  fails closed before the first request.
- **ORC-1 / SIG-4 / SIG-13 — one bad partial could stall a request.** The 1.3.0 library combined the
  first k parts and could hang (`modInverse(0)`) or throw on a malformed one; the poller retried the
  identical input. 2.0.0 tries k-subsets and reports which index is suspect; the member logs it,
  emits metrics, and parks the job until its on-chain parts change.
- **ORC-9 — the repo carried a v3.2.1-era copy of the contract**, so integration tests exercised code
  the chain no longer runs.
- **Image hygiene** — `NODE_ENV=production` is baked in so a missing env cannot load `config/test.json`.

## What did NOT change

- The bytes on chain: `submitpart sig_i` (unpadded lower-case hex of the partial) and
  `setrand`/`markfailed sig` (lower-case hex, exactly modulus width, < n) are identical to v6.0.0.
  The signing library's 2.0.0 release replays 1.3.0 golden vectors bit-for-bit.
- Key material handling, env variable names, the HTTP routes, the poll intervals, and the back-off
  policy for RPC/delivery failures.
- The image's runtime (`node:20-bookworm`, `node index.js`, non-root `node`).

## Deployment

- GitHub: `7.2.0` is tagged on `main` (`9f0ea8c`). GitLab: merge `develop` → `main`, then
  `git tag -a v7.2.0 -m v7.2.0 <main-sha>` and push. The gate measures the increment from
  `RELEASE_BASELINE: v7.1.4` (`.gitlab-ci.yml`), so `v7.2.0` passes G1 without touching the shared
  template.
- The pipeline builds one image, pins its digest into `values-rng-oracle-{1,2,3}-production.yaml`
  and the three members move together. Roll them **one at a time** so two keep signing; each member's
  boot self-check must pass (`/health-check` `bootCheck.ok`) before the next is rolled.
- A member that crash-loops on boot after the roll has a share/index mismatch — check the
  `Boot self-check FAILED` line (names only, never values) before touching anything else.
